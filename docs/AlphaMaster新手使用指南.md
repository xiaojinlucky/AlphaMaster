# AlphaMaster 新手使用指南

这份指南按你当前这台 Windows 电脑和 Linux Slurm 服务器的真实配置编写。先记住一句话：**本机负责选择数据、提交和查看结果；服务器计算节点负责训练；Slurm 决定具体用哪台训练节点。**

## 1. 下次重启电脑后怎么打开

1. 双击桌面的 `AlphaMaster` 快捷方式。
2. 等浏览器自动打开 `http://127.0.0.1:8765`。
3. 如果浏览器没有自动出现，可以手动打开这个地址。

双击快捷方式只会启动本机控制台，**不会自动提交训练任务**。只有你选好数据并点击“开始训练”或“重新训练”后，任务才会提交到服务器。

本机窗口关闭后，控制台会停止，但已经提交到 Slurm 的训练不会因此取消。重新双击快捷方式后，AlphaMaster 会继续查询原来的 run/job 状态。

## 2. 一次训练实际发生了什么

点击训练按钮后，AlphaMaster 会自动完成以下工作，不需要你手动复制文件：

1. 检查 Parquet 文件名、K 线字段、时间范围、行数、来源清单和 SHA-256。
2. 重新选择当前可用的远程计算入口；登录节点只作 SSH 跳板。
3. 把数据和本次源码身份上传到服务器的独立 run 目录。
4. 向 Slurm 提交 CPU 任务；Slurm 根据可用性决定真正的执行节点。
5. 持续显示 `PENDING`、`RUNNING`、`READY` 或失败状态。
6. 训练成功后自动下载检查点、策略和训练历史，并逐个核对哈希。

因此，日常训练不需要你手动导出 ZIP、登录服务器、执行 `scp` 或挑选训练节点。

## 3. 第一次训练的操作顺序

1. 在“01 模型训练”中选择一个符合命名规则的文件，例如 `BTCUSDT_H1.parquet`。
2. 确认界面识别出的品种、周期和 K 线数量正确。
3. 如果想观察详细日志，可以临时打开“调试模式”。
4. 点击训练按钮后等待状态变化：
   - `PENDING`：任务已提交，正在等计算资源；
   - `RUNNING`：任务已在某个 Slurm 计算节点运行；
   - `READY`：服务器训练成功，本机产物下载和哈希校验也成功；
   - `FAILED` / `CANCELLED`：失败或取消，需要看错误信息，不能当作成功。
5. 只有看到 `READY` 才算完整结束。
6. 到“02 策略回测”选择生成的 `best_品种.json`，再判断策略在历史数据上的表现。

## 4. “开始训练”和“重新训练”的区别

- 本地后端中，“开始训练”只会在当前 `timeframe + data_sha256` 身份下寻找最新 run 的最高 step。
- “重新训练”会为当前数据身份创建新的隔离 run 并从头训练，旧 run 和旧检查点保留，不会删除。
- Slurm 第一阶段每次提交都会创建独立 run；网络或 Web 中断只会恢复同一 run/job，跨 READY run 续训尚未开放。
- 想明确做一次全新教学实验时，使用“重新训练”更容易理解和复核。

## 5. 调试模式和普通模式

调试模式只改变日志详细程度，不改变算法、训练步数、CPU 数量、Slurm 调度、结果文件或策略评分。

- 调试模式打开：显示更多请求、文件选择、客户端和服务器日志，适合第一次操作或排错。
- 调试模式关闭：只保留警告和错误，界面更安静，适合日常使用。

本次 BTC 教学训练用调试模式完成；验收后已经恢复为关闭状态。

软连接只提供访问入口，不会复制整套数据。删除项目中的连接和删除 E 盘原始数据不是同一件事；任何删除操作都应先确认目标。

## 7. 数据导出、上传和训练包导入分别要不要手动

- 从 MT5 或其他来源生成新的 Parquet：通常需要你主动选择品种和周期，或运行对应导出流程。
- 点击训练后的数据上传：自动完成，不需要手动传到服务器。
- 训练成功后的结果下载：自动完成，并校验哈希。
- “导出训练包”：可选的手动操作，用于备份或迁移，不是正常训练的必需步骤。
- “导入训练包”：内部训练包 v2 安全校验已经完成审查，但 Web/API 入口仍固定关闭，不能作为用户可用功能操作。

## 9. 正式训练前必须先处理的参数

当前日常界面已经恢复为项目默认 `9000` 步、`12` CPU；Slurm 时限仍是 `30` 分钟。本次 BTC 数据仅 2 步就用了 17 分 50 秒，因此 **9000 步不可能在当前 30 分钟时限内完成**。

在我们共同确定正式训练预算和服务器时限前，不要直接提交 BTC 的 9000 步正式任务。打开 AlphaMaster、查看结果和做回测都不会自动提交任务。

## 10. 训练成功后怎么看结果

先分清两个问题：

1. 工程上是否成功：必须是 `READY`，退出码为 0，产物齐全且哈希通过。
2. 策略是否值得继续研究：需要独立回测、交易成本、样本外表现、稳健性和过拟合检查。训练页面的“最优分数”不能单独证明盈利能力。

## 11. 用 Git 管理自己的 AlphaMaster

当前私有工作仓库是 `github.com/Jinqingchang/AlphaMaster.git`，本机 `main` 跟踪 `origin/main`；`github.com/rosemarycox5334-debug/AlphaMaster.git` 保留为只读上游。

推荐结构是：

- `upstream`：原作者仓库，只用于获取上游更新；
- `origin`：你自己的 GitHub 仓库，用于保存自己的提交。

当前不是 detached HEAD。任何提交仍须逐文件审查和验证，不能使用批量暂存。即使仓库是私有的，`.env`、密钥、训练数据、检查点、数据库、日志和运行产物也不得上传；给外部模型的包还必须排除 `.git` 历史。

## 12. 常见误区

- 双击快捷方式不会自动训练。
- 浏览器关掉不等于取消服务器任务。
- 推荐的远程入口节点不等于实际训练节点；实际节点由 Slurm 决定。
- `READY` 代表工程产物完整，不代表策略能赚钱。
- 调试模式不会让训练更认真或更慢，它只让日志更详细。
- 两步教学训练不能替代正式训练和稳健性评估。
