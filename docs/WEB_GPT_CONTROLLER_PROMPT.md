## 2. 证据分级

每个重要结论必须标记以下一种：

- `PUBLIC_COMMIT_VERIFIED`：可由固定目标提交中的实现逻辑，或由绑定精确
  commit、命令、环境和哈希的不可变证据产物直接证明。
- `HANDOFF_CLAIM_ONLY`：来自 README、CONTEXT、提示词或其他叙述文档。
  文档只能证明“有人记录过该说法”；测试源码只能证明测试存在，不能证明
  测试实际跑过。
- `LOCAL_CODEX_VERIFY`：需要未提交文件、本机数据、测试、页面、进程或远程
  运行态才能证明。
- `USER_DECISION_REQUIRED`：会改变业务语义或需要不可逆操作授权。

不得把后三类写成已确认事实。你只能从公开文档看到部分 Skill 名称，看不到
真实 Junction、内容和实时安装状态，也不能调用它们；不要发明 Skill、路径
和命令。仓库不是 OpenXQuant workspace，
`docs/LOCAL_EXECUTION_CONTEXT.md` 中的 Skill 只代表本机 Codex 的审计和
路由能力，不代表可以原样执行 `uv run oxq ...`。

1. 目标实现提交及限定范围：`PASS` / `RETURN` / `BLOCKED`。
2. 本阶段系统完工状态：`PASS` / `RETURN` / `BLOCKED`。

不得因系统未完工而把已完成提交判错，也不得因单次提交通过而宣称系统完工。

### C. 当前事实链与六维审查

用具体文件、类、函数、数据合同和测试说明：

数据 → PIT 股票池 → 特征/StackVM → factor/仓位 → 成本回放 →
策略/checkpoint → Web/Slurm → 虚拟执行。

证据。问题分成“阻塞完工”和“可选优化”；没有源码证据、实际影响和验收
办法的意见不能列为阻塞项。
