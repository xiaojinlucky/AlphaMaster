# AlphaMaster 多标的组合控制层 v1

## 目标

在不修改单股模型、不停止现役 Slurm 批次的前提下，把同一根已收盘 K 线上的完整股票池信号转换为可比较、可复现、可审计的目标持仓。

首版主链固定为：

```text
单股模型输出
→ 500 根固定窗口逐日重放
→ 单标的 252 点历史分位校准
→ 横截面 Top-K 排序
→ Dropout 换仓缓冲
→ 等权目标仓位
→ 后续虚拟执行与组合账本
```

## 采用与不采用

采用 Qlib 的两个工程思想：

1. 单股预测信号与组合策略解耦。
2. Top-K 持仓配合 Dropout 缓冲，避免每次排名轻微变化就全量换仓。

首版不把 Qlib、FinRL、PyPortfolioOpt 或 Riskfolio-Lib 加入运行依赖。当前最小缺口是“信号可比与组合选择”，不是重写训练平台或引入第二个学习系统。

后续只有在冻结的组合基线已经积累足够样本后，才依次比较波动率倒数、风险平价、市场状态门控和在线学习。强化学习、大模型仓位智能体和遗传搜索不进入首版交易决策核心。

## 冻结股票池与行情合同

组合控制器不接受调用方临时声明的股票列表。一次决策必须绑定
`UniverseContract`，其中保存：

- 股票池名称与快照日期；
- 成分数量；
- 冻结合同 SHA-256；
- 完整且有序的股票代码。

中证 A50 基线通过 `load_csi_a50_universe_contract()` 复核
`universes/csi_a50_20260723.json` 后生成合同。少 1 只、多 1 只或混入池外股票都直接失败。

同一次组合决策还必须满足：

- 全部信号来自同一交易日和同一根已收盘 K 线；
- 周期固定为 `1d`；
- 行情来源固定为新浪后复权 OHLCV：
  `akshare_sina_hfq_ohlcv`；
- 日线时间戳必须是上海时区当日 15:00；
- 每只股票使用不同的训练 run；
- 策略、行情和校准历史均带 SHA-256 身份。

股票池合同、策略参数、决策前权重、完整排名和调仓结果全部进入
`decision_id`。因此任何一项改变都会产生新的决策身份。

## 社区真实问题及本项目处理

- Qlib issue [#543](https://github.com/microsoft/qlib/issues/543) 的维护者说明，`only_tradable=True` 会查看短期未来的可交易状态；设为 `False` 时，停牌或涨跌停又可能让订单失败。用户进一步指出，失败后是否递补下一名股票与真实交易并不一致。
- Qlib issue [#913](https://github.com/microsoft/qlib/issues/913) 的讨论确认，单一涨跌幅阈值不能准确覆盖价格四舍五入、科创板和上市前五日等规则，需要更精确的自定义可交易表达式。

因此，本项目只复用 Top-K + Dropout 的组合思想，不复制其可交易判断。职责边界为：

- `portfolio_manager/controller.py`：只根据同一时点、完整股票池的已知信号生成目标持仓。
- 后续虚拟执行层：处理 T+1、涨跌停、停牌、整手、佣金、印花税、滑点和失败订单递补。
- 回测层：使用与虚拟执行完全相同的交易限制，不能在选股时偷看下一时点是否可成交。

## 信号可比化

不同股票使用不同模型，原始因子值或仓位强度不能直接横向比较。

v1 对每只股票先做“自身历史分位”：

```text
取 752 根已收盘日线
→ 当前时点使用最后 500 根计算原始分数
→ 前 252 个历史时点分别使用各自当时的 500 根窗口重新计算
→ 用 252 个不含当前值的历史分数校准当前值
→ 得到 [0, 1] 历史分位
→ 再在同一时点横截面排序
```

这样只比较“当前信号相对该模型自身历史有多强”，不会把模型 A 的 `0.8` 武断解释为强于模型 B 的 `0.6`。

当前值和历史值都使用未舍入的 `factor_value_raw`。分位相同时只按股票代码确定性排序，不再使用不同模型之间不可比的原始强度或置信度。

历史不足、非有限数、模型版本缺失、数据版本缺失、股票池不完整、K 线时间不一致或时间倒退都会直接失败，不做静默补齐。

## Top-K 与 Dropout

- `top_k`：目标持仓槽位数。
- `dropout_rank`：已有持仓允许保留的最差排名，必须不小于 `top_k`。
- 已有持仓只要仍可入选且排名没有跌出 `dropout_rank`，就优先保留。
- 空槽位再从最高排名的未持仓股票依次补入。
- 单股模型主动离场的股票不能被 Dropout 继续保留。
- v1 每个槽位固定使用 `gross_exposure / top_k`。如果合格股票不足，空槽位保留现金，不把资金集中到少数股票。

单股流水线产物升级为 `alphamaster_signal_simulation_v3`。它会在任何账本副作用前冻结 `signal_input.json`，记录 752 根同源 K 线、策略指纹、行情响应哈希、滚动校准历史和当前完整精度信号。进程崩溃后只能复用这份输入，不能在下一交易日悄悄换一根 K 线。

信号产物同时保存完整精度的 `position_raw`、`strength_raw`、
`factor_value_raw` 和供界面展示的四舍五入字段。A 股生命周期、SQLite
账本、组合适配器和实时管理器只使用完整精度字段做判断；例如真实仓位
`0.04996` 即使展示为 `0.05`，仍按低于 `0.05` 门槛处理为 `HOLD`。

正式入口 `load_pipeline_signal(run_dir)` 不接受调用方自报身份。它直接复核
v2 `pipeline_state.json`、`run_manifest.json`、回测报告及 SHA-256、
`published_strategy.json`、冻结 `signal_input.json` 和 v3 信号产物，
内部生成私有预期身份，再逐项核对 run、股票、策略指纹、行情 SHA-256、
冻结输入 SHA-256、最后 K 线、来源和周期。`lifecycle_event` 还必须与
`signal_simulation.sqlite3` 中同一 `event_id` 的只读账本记录全字段一致；
只改 JSON 动作并同步状态哈希仍会失败。

A50 正式入口 `build_csi_a50_portfolio_decision()` 也不接受调用方传入
`UniverseContract` 或文件路径。它只读取仓库内固定快照并调用严格的中证
A50 加载器；该加载器强制指数代码 `930050`、恰好 50 只成分、完整字段合同、
可重算合同哈希，以及独立固定的可信合同 SHA-256
`987387945fba0cb778b648860bc7579a3cf49e9c3b788596464f714e968bb896`。
正式入口还独立强制每只信号都是 `1d` 和
`akshare_sina_hfq_ohlcv`，即使 50 只股票一致地伪装成另一周期或来源也会拒绝。

`PortfolioDecisionLedger` 不信任 SQLite 中已经存在的 JSON。每次读取都会
严格检查完整字段集合和数值类型，按完整载荷重算 `decision_id`，并与 SQLite
主键和 `bar_ts` 交叉核对。修改排名分数、把数值改成字符串，或篡改后给
payload 重新计算一个新 ID，都不能绕过账本校验。

A 股后处理使用进程内锁加操作系统文件锁；同一 run 即使被两个进程同时发现，也只有一个进程能执行回测和信号阶段。pytest 在导入 Web 全局管理器前同时隔离训练队列和 `local_runs`，不能轮询或改写真实 Slurm 运行态。

硬验收：

1. 经过复核的完整 50 股合同在同一时点可以确定性排序；4/50 或 49/50 必须失败。
2. 输入顺序改变时，决策内容和 `decision_id` 不变。
3. Dropout 能保留仍在缓冲区内的旧持仓。
4. 单股主动离场优先于 Dropout。
5. 缺股票、混来源、混周期、混交易日、时间倒退、非法权重、历史不足、NaN、隐式类型转换和重复股票必须失败。
6. 组合目标账本在重复请求、重启恢复、同 K 线冲突、时间倒退、排名篡改、
   重算 payload ID 和隐式数值转换时失败关闭。
7. 新浪实时拉取的 752 根日线必须与同日冻结训练 Parquet 的时间、float32 OHLC 和成交量逐项一致。
8. 本模块新增前后，现役批次训练源码 SHA-256 必须保持
   `02350ba4e3c696461f2be9f042cb00912568442b3f9986151a79621f571eeb8d`。
9. 执行前必须重算组合决策身份，并精确绑定决策日账户现金、逐批持仓和
   估值行情；只改现金、股数、持仓日期、行情或决策字段都必须失败。
10. 买入只能按行情声明的整手数量；送股等形成的已有零股允许确定性卖出。
    滑点不得产生零价成交，期末现金必须等于期初现金加全部订单现金变化。

2026-07-24 真实验证中，`000333`、`000617`、`000725`、`000792`
四只股票的 752 根数据全部逐项一致。`000333` 使用真实已训练公式完成了
252 个滚动校准点，当前完整精度因子值为
`-0.9319080710411072`，校准历史 SHA-256 为
`8b2058af2d5d9785ccd995674574fed2e3b49a51da83a6ea060fa8914df2e087`。

此前仅用最先完成的 4 只股票生成的
`AM-PORT-71865D22516828A5B4FD8423` 只是一条诊断记录。它不满足当前 50 股合同，不能解释为 A50 组合结果，更不能进入虚拟执行。

最终机器验收为：组合、流水线、行情、账本和控制链定向回归 `226/0`；
完整非实盘套件 `816` 通过、`16` 个既有旧合同失败。三路独立对抗审查
均已 PASS；最后一路复打 8 条完整精度、A50 来源/周期和账本篡改攻击，
`8/8` 都被拒绝，且没有调用 SSH/Slurm 或触碰真实训练队列。
