# AlphaMaster — 问题、需求、修改意见与完成记录

## 1. 用户目标

- 安装并长期维护自己的私有 AlphaMaster fork。
- 在原项目上做轻量二次开发，不做无关的大规模重写。
- 使用 Windows 本机选择/准备数据，通过 Slurm CPU 完成训练并自动取回可验证产物。
- 打通本机与服务器的联通和交互，包括上传、提交、状态、日志、取消、恢复、下载和结果校验。
- 统一 01 模型训练、02 策略回测、03 实时分析的前端视觉。
- 前端采用大字体、舒展排版、清晰边框和一致的侧边栏/卡片/控件。
- 旧 MT5/OKX 数据与未来新增数据能便捷进入训练和回测，而不要求用户手写 manifest。
- 回测能够独立选择测试数据，并严格区分训练集重放、样本外测试和重叠诊断。
- 项目内容、规则、问题、需求、完成状态和验证证据提交到私有 GitHub，供网页版 GPT 通过 GitHub MCP 充当总控。

## 2. 用户明确修改意见

- 01/02/03 的视觉不一致不可接受；不能通过缩小字体、压缩行高或减少留白迁就其他页面。
- 最快、最有效的界面改善是“字体放大 + 排版舒展”。
- Stitch 设计只是参考，必须查看真实运行页面，不能把预览误称为已应用。
- 原始页面的信息和业务内容不得因视觉统一丢失。
- 不要先配置 TradingView。
- 不要把旧 Parquet 缺少 sidecar 解释为数据本身格式错误。
- 必须用 Git 历史区分原作者功能与 fork 新增合同。
- 前端、数据通道等重要任务完成后要由独立审查线程循环复验。
- AlphaMaster 与其他项目必须完全隔离；不能混在一起分析、提交、打包或执行。

## 3. 已发现的主要问题

### 前端

- Stitch 预览和桌面快捷方式启动的生产页面不是同一入口，导致“修改后没有变化”的误解。
- 01、02、03 曾存在侧边栏缩进、激活背景、字号、行高、卡片边框、Tab 拉伸和图表空白带差异。
- 02 回测评估标签在轮询刷新后会被通用“回测绩效”覆盖。
- 数据卡片曾只显示“已注册”，无法区分旧数据用户登记与新版导出器验证。

### 数据与训练

- `NVDA_M5.parquet` 在 Slurm 模式报缺少 manifest；根因是 fork 新增远程身份合同，不是原始数据必然错误。
- 原作者仓库不要求 sidecar；提交 `c3717be` 才为 Slurm 增加该机制。
- 旧 MT5 数据需要可审计登记，但不得冒充新版导出器验证。
- 旧 OKX 归档与新版下载器来源语义不同；下载器必须过滤未完成 K 线。
- 数据来源 allowlist 曾在本地 loader、Slurm control、Worker、进度和训练包之间分叉。
- 训练过程曾用最小策略 JSON 覆盖完整数据身份。
- checkpoint 曾按品种扁平存放，不能安全区分周期、数据哈希和 run。

### 回测与产物

- 策略与测试数据完全同哈希的旧候选合同只能做训练集重放，阻止正常样本外评估。
- 历史策略缺少数据行数、范围和列合同，不能证明样本外边界。
- Slurm 结果曾未完整绑定 `data_start`、`data_end` 和 `columns`。
- README、新手指南和旧 GPT 交接材料曾保留已经过时的候选状态与重新训练语义。
- 旧安全 ZIP 直接基于 Git 树归档，因历史跟踪的 `training_time_XAUUSD.json` 而包含运行态；该 ZIP 未上传 GitHub，后续包必须显式排除并重新扫描。

### 项目边界与移交

- 曾错误地把另一个独立项目的实盘目标写入 AlphaMaster 的上下文和网页版 GPT 总控材料。
- 该做法违反项目隔离要求：外部模型会把本机—服务器联通任务误导为无关的跨仓库规划。
- 现行要求是 AlphaMaster 移交只包含本仓库事实、需求、代码、验证和后续工单。
- 基于错误移交提交 `281db3d1` 生成的旧源码包已作废，不得交给外部模型；修正提交后必须重新打包和扫描。

## 4. 已完成修改

- 三页前端完成统一大字体、舒展排版、侧边栏、标题栏、卡片、表单、按钮和 Tab。
- 真实浏览器验证 01/02/03，无控制台、页面或 HTTP 错误。
- 新增统一数据来源合同 `data_pipeline/dataset_contracts.py`。
- 新增旧 MT5 两阶段 plan/apply 注册，绑定文件哈希、mtime、大小、来源报告与用户确认。
- MT5 导出器和 OKX 下载器自动生成 sidecar；OKX 只保留 `confirm=1`。
- 新增 A 股旧数据严格转换，不静默排序、补行或有损修复。
- checkpoint 按 `timeframe + data_sha256 + run` 隔离；`--from-scratch` 保留旧 run。
- 策略、checkpoint、Slurm run/result、发布指针和训练包贯穿完整数据身份。
- 回测可独立选择测试数据，支持 replay、out-of-sample 和 diagnostic-overlap。
- 回测评分窗口从平仓状态开始，年化依据评估数据实际覆盖范围。
- 训练包 v2 增加 allowlist、路径、数量/大小、CRC、逐文件哈希、身份一致性、暂存验证和失败回滚。
- 相关实现已在独立严格审查后提交 `d4dcb75279387c282e13b56e20e843d6801d4065` 并推送私有 `main`。
- AlphaMaster 的 canonical 上下文、项目规则、移交说明和网页版 GPT 指令已改为单仓库、单项目目标。
- `.env.example` 已改为只描述 MT5 行情读取/数据导出，并使用明显登录占位符，避免暗示存在生产下单能力。

## 5. 尚未完成或仍需决定

- 旧 MT5 668 文件批量计划尚未 apply。
- 正式训练预算、步数、CPU、内存和 Slurm 时限尚未冻结。
- 历史策略缺少完整身份时，需要重新训练或另行迁移，不能直接宣称可做严格样本外。
- Web/API 的训练包导入入口仍固定关闭。
- TradingView 仍暂缓。
- 完整 unit 仍有 8 个既有失败，不能宣称全仓全绿。
- Git 当前树仍跟踪 `training_time_XAUUSD.json`；是否删除当前文件、是否治理历史需要单独授权。
- 工程链路通过不代表策略盈利；正式研究还需要独立样本外、成本、稳健性与过拟合检验。

## 6. 当前交付原则

网页版 GPT 只通过 GitHub MCP 读取 AlphaMaster 私有仓库，并围绕本机—服务器联通、训练交互、数据/产物身份、回测和前端可用性充当总控。外部模型的路线图、工单和硬验收必须由本地 Codex 按真实 skills、memory、Windows/Slurm/MT5 状态、当前代码和测试证据修订后才能执行。
