# AlphaMaster — Codex 项目规则

本文件记录本项目实际使用的执行规则，供本地 Codex、独立审查者和外部规划模型理解边界。它不复制全局规则全文，也不包含凭据或其他项目的私有状态。

## 1. 项目边界

- AlphaMaster 是基于原始 fork 的轻量二次开发项目，保留因子训练、策略回测和实时信号能力。
- 当前优先目标是保持既有 AlphaGPT/StackVM/固定仓位边界，先关闭会失真历史成绩和实盘语义的未来函数、时间错位与回测过拟合；Windows—Linux Slurm 联通是基础设施，不得反客为主。
- 本项目与其他仓库完全隔离。不得联合分析、联合规划、联合提交、联合打包或联合执行，也不得引入其他项目的业务目标、上下文、运行态和源码。
- 当前不建设券商订单执行通道，不得把实时信号展示描述为自动交易。
- TradingView 当前暂缓；不得把未配置状态描述为可用。

## 2. 设计与开发

- 开始任务先读 `CONTEXT.md`、`lessons.md`、`README.md` 和本文件。
- 从第一性原理出发：先确认用户真实目标、现有代码事实、数据合同和客观约束，再形成最小技术方案。
- 开发遵守剃刀定律：只增加关闭当前问题必需的代码、状态和依赖；成熟实现能复用时不自造轮子。
- 需求仍不清楚且不同答案会实质改变结果时，一次只问一个问题；说明选项、举例和推荐理由，逐轮确认到约 95% 把握后再给方案。
- 不静默降级、不猜测字段、不用启发式修补掩盖数据身份、状态或远程错误。
- manifest 不是核心算法的固有要求：本地 Parquet 可无 manifest；Slurm 远程训练必须有可审计 sidecar。
- 旧数据登记与新版导出器验证必须使用不同来源身份，禁止混称“已验证”。
- 训练数据身份与评估数据身份必须分别记录；样本外回测不能伪装成训练集重放。
- 只修改当前目标直接相关部分，不顺手重构或调整无关业务。

## 3. 训练与远程安全

- 登录节点只作 SSH 跳板；交互入口由节点选择器确定，训练节点由 Slurm 调度。
- 远程失败不得静默退回本机训练。
- `READY` 必须同时证明目标策略、checkpoint、训练历史和结果 manifest 属于同一 run、同一数据身份且哈希匹配。
- 正式训练预算、步数、CPU 和时限未确认前，不启动长训练。
- 开发、文档、审查和打包阶段不得提交训练任务或连接任何交易执行接口。

## 4. 数据、凭据与 Git

- `.env`、真实 `web_settings.json`、token、密码、私钥、券商账户信息不得进入 Git、日志、测试夹具或移交包。
- 原始行情/交易/训练数据、数据库、checkpoint、模型权重、训练历史、运行日志和运行态文件不得提交。
- 当前历史树仍跟踪 `training_time_XAUUSD.json`；不得把这一遗留当作继续提交运行态的先例。删除当前文件或净化历史需单独明确授权。
- 配置示例只能使用空值或明显占位符。
- 混合工作区只暂存用户确认的精确路径，禁止 `git add .` 和 `git add -A`。
- 提交前必须核对完整 staged diff、密钥扫描、文件大小/类型、私有远程权限和实时远程 SHA。
- 不擅自创建分支、worktree、tag，不改写历史，不强推。

## 5. 验证与审查

- 测试报告只报告真实通过/失败数量；超时或没有最终汇总时不得推断。
- 验收遵守墨菲定律：覆盖空输入、格式错、身份漂移、权限不足、超时、网络未知、并发、重启、历史状态和误用，不只证明正常路径。
- 重要数据、训练、回测、安全和发布变更必须经过独立审查者六维复验：
  - 需求完整性
  - 逻辑正确性
  - 边界情况
  - 代码质量
  - 测试覆盖
  - 实际运行结果
- 审查问题必须分为“阻塞落地的问题”和“可选优化”；只强制修复前者，不以审查为由主动扩张需求或重构已满足要求的部分。
- 每条阻塞修改建议必须说明违反的需求、实际风险和复验方法；没有明确依据时保留原方案。
- 阻塞问题不为零时，不得把候选描述为稳定完成；修复后交回同一独立审查者复验，循环到阻塞项清零。

## 6. 外部模型协作

- 网页版 GPT 只读取 AlphaMaster 私有仓库的已提交快照，不得读取或比较其他项目。
- 网页版 GPT 看不到本机 skills、memory、进程、凭据、数据和未提交工作区。
- 外部模型只充当总控、架构与工单审查者，不直接修改代码或授权运行。
- 外部工单必须先由本地 Codex 按 `docs/LOCAL_EXECUTION_CONTEXT.md` 重新核验路径、工具、命令、官方 API、环境和安全边界。
- 用户确认真正业务分叉后，才进入本地开发或高风险运行。
