# AlphaMaster — Codex 项目规则

本文件记录本项目实际使用的执行规则，供本地 Codex、独立审查者和外部规划模型理解边界。它不复制全局规则全文，也不包含凭据或其他项目的私有状态。

## 1. 项目边界

- AlphaMaster 是基于原始 fork 的轻量二次开发项目，保留因子训练、策略回测和实时信号能力。
- 当前优先目标是普通大 A 多标的训练、成本回测和只做多虚拟信号，按两条互不阻塞的主线推进：运营恢复线先对账已完成的 Slurm `570548`，再收敛本地状态并决定是否恢复剩余队列；研究研发线先冻结已有 255 个沪深300权重时点的 PIT 可知/生效合同和 949 代码覆盖矩阵，再做历史覆盖扩展、动态股票池组合 replay、时点成交状态、现有账本生产化和 sealed OOS。50 只基线是历史诊断与后续批次目标，不是外部审查或 PIT 研发的前置条件。外部规划模型只提供方向、依赖和反方意见，由本机 Codex 按真实 Skills、数据和现有代码本地化。未来函数、时间错位、回测过拟合和一次性封存评估仍是成绩真实性硬门。
- 本项目与其他仓库完全隔离。不得联合分析、联合规划、联合提交、联合打包或联合执行，也不得引入其他项目的业务目标、上下文、运行态和源码。
- 当前发布基线没有券商订单执行通道，不得把实时信号展示描述为已自动交易。用户目前没有可验证的 QMT/PTrade/目标券商实盘渠道，因此现阶段只交付服务器训练、成本回测、虚拟信号和可选飞书推送；不得填入凭据、连接真实账户或发单。
- TradingView 当前暂缓；不得把未配置状态描述为可用。

## 2. 设计与开发

- 开始任务先读 `CONTEXT.md`、`lessons.md`、`README.md` 和本文件。
- 从第一性原理出发：先确认用户真实目标、现有代码事实、数据合同和客观约束，再形成最小技术方案。
- 开发遵守剃刀定律：只增加关闭当前问题必需的代码、状态和依赖；成熟实现能复用时不自造轮子。
- 需求仍不清楚且不同答案会实质改变结果时，一次只问一个问题；说明选项、举例和推荐理由，逐轮确认到约 95% 把握后再给方案。
- 不静默降级、不猜测字段、不用启发式修补掩盖数据身份、状态或远程错误。
- manifest 不是核心算法的固有要求：本地 Parquet 可无 manifest；Slurm 远程训练必须有可审计 sidecar。
- 旧数据登记与新版导出器验证必须使用不同来源身份，禁止混称“已验证”。
- 训练数据身份与评估数据身份必须分别记录；样本外回测不能伪装成训练集重放。
- 只修改当前目标直接相关部分，不顺手重构或调整无关业务。
- 上游同步一律选择性移植，不整体 merge：量化、金融、模型训练和通用数据处理优先与上游保持一致；AI 大模型接入、Slurm 训练调度、前端页面和实盘接入方向是 fork 定制边界，未经用户明确决定不得覆盖或删除。

## 3. 训练与远程安全

- 登录节点只作 SSH 跳板；交互入口由节点选择器确定，训练节点由 Slurm 调度。
- 远程失败不得静默退回本机训练。
- `READY` 必须同时证明目标策略、checkpoint、训练历史和结果 manifest 属于同一 run、同一数据身份且哈希匹配。
- 正式训练预算、步数、CPU 和时限未确认前，不启动新的长训练批次；已经冻结请求和源码身份、并由用户批准运行的持久批次不受后续开发影响。
- 用户已明确要求训练不可因开发、文档、审查、调研或新指令中断。现役批次运行期间不得取消、重提、改写源码身份或静默换成本地训练；只读监控、本地开发、回归和审查并行进行。需要替换现役作业时，必须先证明原作业终态并取得用户授权。

## 4. 数据、凭据与 Git

- `.env`、真实 `web_settings.json`、token、密码、私钥、券商账户信息不得进入 Git、日志、测试夹具或移交包。
- 原始行情/交易/训练数据、数据库、checkpoint、模型权重、训练历史、运行日志和运行态文件不得提交。
- 外部审查需要时，可以提交脱敏、带时间戳、不可被程序作为控制输入的运行
  摘要；摘要只能记录必要的 job/run 标识、状态和哈希，不得包含日志正文、
  凭据、节点私密配置、原始数据或可恢复账户/队列状态的机器文件。
- 当前历史树仍跟踪 `training_time_XAUUSD.json`；不得把这一遗留当作继续提交运行态的先例。删除当前文件或净化历史需单独明确授权。
- 配置示例只能使用空值或明显占位符。
- 混合工作区只暂存用户确认的精确路径，禁止 `git add .` 和 `git add -A`。
- 提交前必须核对完整 staged diff、密钥扫描、文件大小/类型、实时远程 SHA 和远程写权限。用户已明确要求 `xiaojinlucky/AlphaMaster` 始终保持公开，仓库可见性不是发布阻断项；但公开仓库仍只能提交当前任务明确授权且通过安全检查的精确快照。当前 goal 内的提交与推送已有持续授权，不再逐次重复询问；清单外文件、删除、重命名或安全阻断仍须停止。
- 不擅自创建分支、worktree、tag，不改写历史，不强推。

## 5. 验证与审查

- 测试报告只报告真实通过/失败数量；超时或没有最终汇总时不得推断。
- 验收遵守墨菲定律：覆盖空输入、格式错、身份漂移、权限不足、超时、网络未知、并发、重启、历史状态和误用，不只证明正常路径。
- 重要数据、训练、回测、安全和发布变更必须经过独立审查者六维复验：
  - 需求完整性
  - 逻辑正确性
  - 边界情况
  - 代码质量
  - 测试覆盖
  - 实际运行结果
- 审查问题必须分为“阻塞落地的问题”和“可选优化”；只强制修复前者，不以审查为由主动扩张需求或重构已满足要求的部分。
- 每条阻塞修改建议必须说明违反的需求、实际风险和复验方法；没有明确依据时保留原方案。
- 阻塞问题不为零时，不得把候选描述为稳定完成；修复后交回同一独立审查者复验，循环到阻塞项清零。

## 6. 外部模型协作

- 当前 goal 的唯一外部审核者是网页版 GPT；BioMNI 已退出当前总控链，其提示词只保留为历史证据。网页版 GPT 只读取 AlphaMaster 已提交快照，不得读取或比较其他项目。用户已明确要求本仓库始终公开，以保证网页版 GPT 能直接读取；不得再要求改为私有。任何公开提交仍不得包含凭据、真实配置、原始数据、数据库、模型、checkpoint、训练历史、原始日志或机器可消费的运行态文件；只允许前述脱敏摘要证据。
- 外部模型看不到本机 Skill 的真实 Junction、内容与实时安装状态，也不能
  调用它们；它们同样看不到 memory、进程、凭据、真实数据、测试现场、
  Slurm 和未提交工作区，也不能直接调用本机能力。AlphaMaster 不是
  OpenXQuant workspace，外部模型不得把猜测的 Skill、路径或 OpenXQuant
  CLI 命令写成硬执行单。
- 外部模型负责方向、架构、依赖、优先级和对抗审查；本机 Codex 负责刷新
  现场、选择真实 Skill、删除重复建设、映射现有模块、修改代码、测试和
  真实运行。外部工单不是执行授权。
- 本机 Codex 收到工单后必须按 `docs/LOCAL_EXECUTION_CONTEXT.md` 标记
  `接受 / 改写 / 删除`。关键路径确定后立即推进，身份链证据、测试复现、
  页面真值等独立工作并行，不退回“一次只做一张最小工单”。
- 已授权范围内的可逆本地实现、只读验证，以及当前 goal 内通过精确暂存和
  安全门禁的提交/推送不重复请示；只有业务语义分叉、正式训练、数据库操作、
  删除、清单外文件、重命名、安全阻断或其他新增不可逆外部动作才交回用户
  决定。
