## 已确认的现实边界

- AlphaMaster 的全部模型训练都在用户服务器上通过 Slurm 单节点运行；
  Windows 本机只负责数据准备、控制、回测、信号和前端。
- 当前没有可验证的 QMT、PTrade 或目标券商实盘渠道。本阶段只生成
  买入、加仓、减仓、离场、止盈和止损等虚拟信号，不连接券商、不发单。
- 当前先用 2026-07-23 冻结的中证 A50 成分做 50 只串行工程基线。
  它是龙头候选池，不是已经证明“近一年轮动最好”的最终 50 只。
- 最终门槛是 50 只股票每只在扣除成本后的独立封存样本外 Sharpe
  都大于 1。训练分数和同训练数据 replay 不算最终通过。
- 训练批次必须持续运行；架构研究和代码开发不能要求中断、重训或取消
  现役 Slurm 作业。
- 首版组合控制已经选择确定性的“单股滚动分位校准 → Top-K →
  Dropout 缓冲 → 等权目标”。强化学习、大模型智能体和遗传算法不能
  仅因为听起来先进就取代这条可审计基线。

## 当前代码已经解决

- 组合决策绑定经过复核的完整冻结股票池合同，4/50 或 49/50 不能生成
  A50 目标组合。
- 每只股票取 752 根新浪后复权日线：500 根用于当前模型窗口，前 252
  个历史时点分别用各自的 500 根窗口重放，再做单标的历史分位校准。
- 组合只接受同一交易日、同一上海 15:00 收盘时点、同一 `1d` 周期、
  同一新浪后复权来源的完整信号。
- 单股产物使用 `alphamaster_signal_simulation_v3`，在账本副作用前
  冻结市场快照；重试不能换成下一交易日。
- 单股决策、虚拟持仓和组合校准一律读取未舍入的 `position_raw`、
  `strength_raw`、`factor_value_raw`；四舍五入字段只供界面展示，不能把
  `0.04996` 显示成 `0.05` 后误触发买入。
- 组合正式入口从 READY 流水线状态、run manifest、回测报告、发布策略、
  冻结信号输入和输出哈希内部生成身份，不接受调用方自报 expected；随后核对
  run、股票、策略、行情哈希、最后 K 线、来源和周期，并只读复核 SQLite
  生命周期事件，防止输出 JSON 把买入伪造成离场。
- 组合决策、目标状态和历史通过 SQLite 审计；每次读回都会严格检查字段
  类型、重算 `decision_id` 并与 SQLite 主键和 K 线时间绑定。状态篡改、
  排名篡改、数字文本、时间倒退和同 K 线冲突都会失败关闭。
- A 股后处理有跨进程唯一租约；测试运行根目录与真实 Slurm 运行态隔离。

## 需要你调研并作出决策的核心问题

### 1. 单股模型如何形成多标的持仓

请广泛检索 GitHub、论文、技术博客和真实社区讨论，重点比较：

- 独立单股模型的输出怎样做跨股票可比化；
- Top-K、Top-K + Dropout、横截面动量、相对强弱、风险预算、
  Hierarchical Risk Parity（分层风险平价）等成熟路线；
- 每日、每周、双周或事件触发调仓的真实成本和稳定性；
- 旧持仓继续保留、新标的进入、信号缺失、模型失效和部分股票不可交易时
  应怎样确定性处理；
- 不同单股模型之间怎样切换，怎样避免只选中近期噪声或完成训练最早的股票。

优先寻找能直接复用的成熟开源模块。请明确区分“可直接接入”“只借鉴工程
思想”“当前不采用”。

### 2. 大 A 执行约束

即使当前只做虚拟信号，也要让回测和虚拟组合采用同一套可交易语义：

- T+1；
- 停牌；
- 主板、创业板、科创板不同涨跌停规则；
- 上市前若干交易日特殊规则；
- 100 股整手、零股余量；
- 佣金、印花税、过户费和滑点；
- 调仓订单失败后是否递补下一名股票。

请优先评估 Qlib 等成熟框架已有实现和已知 issue，不要重新写一个未经验证的
通用撮合器。

### 3. 前沿算法和智能体是否值得进入

分别评估以下路线能否在现阶段产生可衡量增益：

- 大模型投资智能体；
- 神经网络组合控制器；
- 强化学习；
- 遗传算法；
- 市场状态识别；
- Mixture of Experts（专家混合）或模型路由；
- 在线学习和概念漂移监测。

每项必须回答：

1. 它解决现有确定性基线的哪个具体缺口；
2. 需要什么数据量和标签；
3. 怎样做严格样本外验证；
4. 会增加哪些不可审计或过拟合风险；
5. 是否有成熟开源实现和真实用户踩坑；
6. 现在接入、积累数据后再接入，还是明确不接入。

不要让大模型直接输出任意仓位。若引入智能体，优先让它做只读诊断、异常
解释、候选方案比较或受限动作选择；所有最终组合动作仍需经过确定性合同和
账本。
